## 骨架

按文档类型选骨架，章节一律 `N.` 编号，二级用 `N.M`。

### 问题分析 / 故障复盘

```
1. 概述          1.1 结论（编号列表，每条一句话）  1.2 影响面（表）
2. 缺陷分析      触发条件 / 流程差异（mermaid）/ 调用链 / 代码位置（表）/ 日志验证（表）
3. 数据分布      口径声明 + 基线对比 + 汇总指标 + 相关性
4. 专项比对      方法 / 结果 / 结论（有则写，如请求样本比对、性能对比）
5. 复发或变化    再次发生时按时间追加，不改写历史章节
6. 修复方案      修改点 / 已否决方案（表）/ 上线顺序 / 同类风险
7. 交付材料      给下游团队可直接使用的清单
附录            长清单、原始数据
```

### 技术方案

```
1. 需求          背景 / 目标 / 非目标
2. 方案          整体流程（mermaid）/ 数据结构 / 关键技术点
3. 接口          proto 或 HTTP 定义，客户端要看的放最前
4. 存储          表结构 / Redis key / 索引
5. 修改文件清单  表：文件 / 位置 / 说明
6. 边界与风险    幂等 / 并发 / 失败回滚 / 性能
附录            备选方案对比
```

如项目已有自己的文档编写约定，以项目约定为准。默认不写实施清单、上线计划、灰度策略、详细测试用例、FAQ，除非明确要求。

## 首部元信息

正文第一块用表格交代上下文，不用散文：

```markdown
| 项 | 内容 |
|---|---|
| 环境 | 生产环境（prod） |
| 服务 | svc-a、svc-b |
| 接口 | `/api/v1/xxx/callback` |
| 数据窗口 | D 日全天；D+1 日 08:00–10:00 |
```

## 编号与标题

| 规则 | 说明 |
|---|---|
| 二级标题必须编号 | `## 3. 失败量分布`，读者靠编号定位和引用 |
| 标题是名词短语 | 命名内容，不描述发现。不用问句、不用逗号断句、不以句号结尾 |
| 不用复合标题 | `## 5. 复发分析` 而非 `## 五、复发：调用方改用先单笔后批量绕过` |
| 长度 ≤ 24 字 | 超了说明标题在承担正文的活 |
| 层级不跳级 | H2 下面直接是 H3，不出现 H2→H4 |
| 跨章引用写编号 | 「见 7.1」而非「见前面请求模板那节」 |

## 表格

优先级高于散文。以下内容一律用表：

- 任何「A 对应 B」的映射，如文件与行号与说明、错误码与含义、配置项与默认值
- 任何多维对比（两个时段、两个方案、改前改后）
- 时间序列事件（日志因果链）
- 已否决方案及其原因

要求：

| 要求 | 说明 |
|---|---|
| 必须有表头分隔行 | `\|---\|---\|` |
| 各行列数一致 | 缺项填 `—` 或 `·` |
| 数字列对齐口径 | 同列单位一致，百分比统一小数位 |
| 不在表内塞长句 | 超过一行的说明移到表下方 |

## Mermaid

判断标准：这张图能表达文字难以线性描述的分支或并发。能用三行文字讲清的流程不画图。

| 场景 | 图类型 |
|---|---|
| 两条路径的分支差异 | `flowchart TD` |
| 跨服务调用与时序 | `sequenceDiagram` |
| 状态流转 | `stateDiagram-v2` |
| 单服务内的时间因果 | 不画图，用表格 |

语法陷阱（`doc_lint.py` 会检查）：

```
节点标签含 () : / 时必须加引号
  错：G[handleFooAsync (foo.go:123)]
  对：G["handleFooAsync foo.go:123"]

标签内换行用真实换行，不用 <br/>
  G["handleFooAsync
foo.go:123 提前 return"]

边标签不要放括号
  错：C -->|否（已存在）| D
  对：C -->|否，记录已存在| D
```

关键节点用 `style` 标红，让读者一眼看到问题点：

```
style G fill:#f8ddd9,stroke:#a5332a
```

## 数据口径

任何统计数字都要能被别人复核。在数据章节开头或文档首部声明：

- 数据来源（哪个日志关键字、哪张表、哪个平台）
- 时间窗口（绝对时间带时区）
- 统计对象（算什么、不算什么）
- 抽样还是全量，有无截断

示例：

> 统计口径：`handleCallback success` 与 `saveOrderRecord failed` 全量导出，分段拉取无触顶。统计对象为通过签名校验后进入落库阶段的回调请求，不含校验阶段被拒绝的部分。

没有口径的数字在评审时会被直接质疑，等于白写。

## 附录

正文只放结论和代表性样本，以下内容下沉到附录：

- 超过 10 行的 ID 清单
- 原始日志片段
- 完整的枚举值表

附录标题用 `## 附录 A：xxx`，正文引用写「见附录 A」。

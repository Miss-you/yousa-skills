# EACC 群聊按日提炼（SOP + 人物加权 + 验收）

## Overview

从 eacc-chat MCP 索引中按日期拉取群聊消息，提炼**对股票投资决策有价值的信息**，产出带溯源、带发言人权重的 Markdown 笔记，并强制执行数据验收。

目标不是"总结聊了什么"，而是**帮用户高效获得可用于投资决策的：方法论、关键判断、关键 Know-how、高价值事实**。

核心原则：
1. **每条结论必须能通过 local_id 溯源到原始消息**；
2. **信息价值 = 内容价值 × 发言人权重**——同一句话，出自高权重人物和出自噪音账号，处理方式完全不同；
3. **验收不通过不得交付**。

## 参数与产出约定

- 时间参数：`YYYY-MM-DD` 按 +08:00 解释；`end_time` 是**排他**上界 → 提取 7月4日 用 `start=2026-07-04, end=2026-07-05`。
- 产出文件：`投资/群聊提炼/YYYY-MM-DD-群聊提炼.md`（Obsidian 库内）。

## 人物加权（每次运行必须加载）

权重清单：`sender-trust-roster.json`——路径因环境而异，使用者需自行配置（如放在群聊归档数据目录下，并在项目级 CLAUDE.md 或本 skill 的本地副本中记录实际路径）。格式约定：JSON 数组，每项至少含稳定 ID `sender_username` 与 `weight`。

- **只按 `sender_username`（稳定 ID）匹配，绝不按昵称**——昵称会随时更改。转录必须保留 sender_username。
- 未列名单者权重 1.0。
- **positive（≥1.3）**：其观点、判断、心法优先收录；"关键判断"小节按权重排序；引述时标注权重，如 `张三[1.7]`。
- **negative weight=0.0（filter）**：不得作为方法论/判断/Know-how/事实的信源；其发言只可作为群体情绪的佐证。
- **negative weight=0.3（downweight）**：默认不收录其单独观点；仅当被高权重人物明确认可/接续时收录，并注明。
- roster 之外，若当日有明显身份背书的新信源（如自称从业者且被群主认证），可临时按 1.2 处理并在产出中注明"未入册"。

## SOP

### Step 1 摸底

`eacc_time_activity`（bucket=hour）获取当日总消息数 N 与分时分布。记录 N（验收①）与讨论峰 Top3（验收②）。

### Step 2 拉取与清洗（必须子代理执行）

原始 JSON 含大量图片/视频 XML blob，**禁止在主上下文分页拉取全天消息**。派 general-purpose 子代理，提示词必须包含：

- 用 ToolSearch 加载 `mcp__eacc-chat__eacc_query_messages`；
- `eacc_query_messages(start, end, limit=200)` 循环 `next_cursor` 直到 `has_more=false`；
- 清洗规则：
  - `text` → 保留 text_content 全文；
  - `rich_media` → appmsg：`[转发] parsed.title — parsed.description`；appmsg_quote：`[回复 refermsg.displayname] text_content`；
  - `image/video/sticker/voice/non_text/system` → 丢弃，仅计数；
- **行格式：`HH:MM 显示名[sender_username](local_id): 内容`**（sender_username 供权重匹配）；
- 写入 scratchpad 文件（不要在最终回复里贴全文），回复：总条数、分类型计数、最终 has_more、source_database/source_table、文件路径与行数。

### Step 3 阅读与话题识别

主代理通读转录（大交易日 2000+ 行时分页读，每页 ≤500 行；提炼与判断不得转包给拉取子代理），按 **热度 = 相关消息数 × 参与人数 × 持续时长** 取 Top2 核心话题。**热度只在投资相关消息集内计算**：纯娱乐/八卦/生活话题即使占据全天最高峰也不得作为核心话题，只在"情绪与共识"小节用一句话记录其存在（它反映当日群体状态）。每个话题必须含：
1. 话题名；2. 时间段与主要参与者（标权重）；3. 讨论脉络：谁提出 → 核心论点 → 分歧点 → 结论或未决；4. 代表性原话引述 2–3 条，格式 `显示名[权重](local_id)：「逐字原文」`。

### Step 4 投资价值信息提炼（六个小节，缺一不可，无内容写"无"）

| 小节 | 收录标准 | 关键动作 |
|---|---|---|
| 方法论 | 可复用的分析/交易/风控框架（如压力测试仓位法、催化剂清单法） | 提炼成可执行的一句话，注明出处 |
| 关键判断 | 高权重人物对市场/板块/个股的方向性判断与理由，含其仓位动作 | 按权重降序；判断+理由+仓位证据 |
| 关键 Know-how | 操作层面的诀窍：工具用法、渠道、规则细节（如 TRS 通道、ADR 衍生品规则、链上现货看价渠道） | 这是用户最看重的类别，宁多勿漏 |
| 高价值事实与数据 | 有数据、有来源的事实（价格/财报日期/产业数据/研报要点） | 标注一手/转发/二手转述 |
| 情绪与共识 | 群体情绪与分歧结构，必须给证据（谁、原话、多少人附和） | 分歧双方都要呈现 |
| 未证实传闻 | 无来源但引发认真讨论的事实断言 | 单独隔离，标【未证实】，记录谁信谁驳 |

过滤规则：
- 纯情绪表达/斗图/寒暄/生活闲聊 → 丢弃（除非作为情绪小节的证据）；
- weight=0.0 者的观点 → 不入前四类小节；
- 转发文章标题 ≠ 群内观点：必须区分"转发内容"与"群内解读/反应"。

### Step 5 写入产出文件

frontmatter 含 `date / group / message_count / coverage / generated_by`。正文顺序：核心话题一、二 → 方法论 → 关键判断 → 关键 Know-how → 高价值事实与数据 → 情绪与共识 → 未证实传闻 → 验收记录表。

### Step 6 数据验收（强制，主代理执行，不得由 Step2 子代理自评）

| # | 验收点 | 方法 | 通过标准 |
|---|---|---|---|
| ① 覆盖率 | 子代理拉取条数 vs Step1 的 N | 相等，且 has_more=false |
| ② 话题准确 | 话题时间段 vs 分时高峰；必要时 `eacc_search_messages` 关键词抽查 | 两话题合计覆盖至少前二讨论峰 |
| ③ 引述保真 | 抽 ≥2 条引述，用 `eacc_get_context`（source_database/source_table/local_id）回查 | 原文逐字一致、发送者一致 |
| ④ 加权合规 | 核对产出中所有信源的 sender_username vs roster | 前四类小节无 0.0 信源；关键判断标注了权重 |
| ⑤ 过滤正确 | 复读产出 | 无纯情绪条目；无来源断言均已隔离标注 |
| ⑥ 完整性 | 两话题四要素、六小节 | 齐全（可为"无"） |

验收结果写入产出文件"验收记录"表。任一不通过 → 回到对应 Step 修正后**重新走验收**；把根因追加到本文件"迭代记录"。

## Common Mistakes

| 错误 | 修正 |
|---|---|
| 在主上下文直接分页拉全天消息 | 图片 XML 撑爆上下文；必须子代理拉取＋清洗到文件 |
| end_time 用当天日期 | end 是排他的，会少一整天；用次日 |
| 转录只留昵称、丢了 sender_username | 权重无法匹配（昵称会变）；行格式必须带稳定 ID |
| 引用 0.0 权重者的"干货"（如财报日期） | 高置信信息必须换成高权重信源或独立佐证，否则降级到情绪/传闻 |
| 引述凭印象改写、拼接 | 验收③必挂；逐字复制 text_content |
| 把转发文章标题当作群内观点 | 标注是谁转的、群内如何反应 |
| 只提炼新闻，漏掉 Know-how | Know-how（渠道/规则/工具细节）是用户最看重的，单列小节强制检查 |
| 子代理既提炼又自己验收 | 验收必须主代理独立抽查 |

# 切分与证据验收

## 在处理前明确验收范围

记录用户目标：完整原曲、混编中的片段或其他范围，以及曲序／格式偏好。沿用源顺序，除非用户要求另排；官方曲序不能代替内容定位。

为每首记录：source_id、原始与规范曲名、输出文件、start/end（相对该源的秒数）、参考 URL／版本、定位窗口与偏移、负例结果、边界可接受区间、实际输出区间、是否转码、各项验收状态。多源补齐需独立坐标；不能把缺失首曲的时间加到整个混编上。

阈值、窗口与允许误差根据素材预先约定。实际不达标时记录失败，调查声道、延迟、速度、混响、不同混音或版本；改方法须说明原因和新的反例结果，不把旧失败改写成通过。

## 内容对应

1. 从参考挑多个非静音、有辨识度的窗口；前中后是起点，不能证明整首完整。
2. 先全段搜索，不把预设歌名或顺序作为搜索范围。长曲、循环、变奏、重排或异常时，再做密集窗口与局部对齐。
3. 用归一化互相关、频谱随时间变化或合适指纹匹配；记录分析采样率、窗口长度、声道和变换。纯音量、总时长、单幅频谱不能确认曲目。
4. 同时测错曲、共享主题和重复循环。若正负分数接近或有多个同样好的位置，增加辨识窗口或独立来源；仍无法消除就标待核实。
5. 偏移随时间跳变或漂移时，检查剪辑、循环增删、播放速度与版本。不要为了提高分数改动音乐。

## 切点选择与反例

| 情况 | 处理 | 验收证据 |
| --- | --- | --- |
| 干净低电平间隔 | 核对相邻曲内容后在间隔中选点 | 前曲尾声、后曲起音完整，实际切点在容许区间 |
| 曲中静音或弱奏 | 保留，除非有其他证据证明换曲 | 与参考结构及静音两侧音乐一致 |
| 缓慢渐弱 | 比较多个阈值，保留可疑尾声 | 候选尾部能量／频谱、参考尾部与过渡片段 |
| 连续转场／交叉淡化 | 标出重叠区，寻找独立完整录音 | 单一切点无法分离的事实及交付限制 |
| 缺曲、缺头尾、广告插入 | 查源并分别标识补入或删除区间 | 内容匹配、来源、编辑前后区间明细 |

对每个不同类型的边界主动寻找反例；发现一个阈值误切尾声，就检查所有受该阈值影响的边界，不必重跑无关研究。

保存转场前后数秒的短样本及首尾样本供试听。真实试听要写清覆盖范围；没有试听只记录客观信号结果。弱信号可测不等于人人能听见。

## 编码包和实际播放要分别验证

- 流复制只能落到可用包／帧边界。记录实际起止与预期差异，不能把命令中的小数秒当成实际输出边界。
- Opus、AAC、MP3 等可能涉及解码预热、pre-skip、编码延迟、尾部 padding／裁剪。包序列相同不保证每个新文件解码开头与源一致。检查解码样本数、局部对齐、开头和尾部；不能仅看容器 duration。
- 尽可能比较源与输出对应区间的解码信号，正确处理时基、延迟和尾裁剪。跨容器或有损转码时不要硬要求逐样本／包哈希相等。
- 无新增有损转换且包未改写的路径，可逐包核对负载 SHA-256、顺序和归属，检测丢包或重复；需要解码预热的重复包应独立标记，不算重复可听内容。对首段、末段和每个接缝检查实际解码效果。
- 若边界精度与保留编码冲突，优先满足用户目标：记录限制，必要时从最佳源仅编码一次以得到正确边界，并如实标注。

## 文件与标签验收

下述完整解码、接缝和试听检查用于新增切分、转码或修复。单纯改标签／封面且无新异常时，只校验本轮字段、既有标签保留、图片、编码负载不变和交付包；不重复映射、切分或听觉验收。

以下是可改写的命令示例；执行时用参数数组或正确的 shell 引号，勿将歌名直接拼入命令：

```sh
# 完整解码到空输出；逐文件保存错误和退出码。
ffmpeg -v error -xerror -i "track.opus" -map 0:a:0 -f null -
# 用于同一文件改标签前后，核对编码音频负载未改变。
ffmpeg -v error -i "track.opus" -map 0:a:0 -c:a copy -f hash -hash sha256 -
```

第二条只验证标签操作没有改变音频负载，不证明切点正确、版本完整或源无损。严谨的切分保真还需逐包记录和解码检查。

每个导出文件读回格式、音轨数、时长、曲名、专辑、曲号及本轮新增标签。封面核对类型、MIME、解码尺寸和图片字节；如做用户授权的格式转换，记录转换后图片哈希。

试听至少覆盖实际切点两侧、每首头尾、已发现的异常窗口；若未做，不将完整解码无报错写成“试听通过”。有播放器时抽检真实显示；未测则只声称标准标签已读回，不保证所有播放器显示。

## 停止条件与交付状态

- 达到预设证据要求且无未解释的重大异常后停止扩测。
- 某一歧义追加更细对齐或另一个来源仍未解决时，记录候选和缺失证据；只有出现新线索才继续同方向检索。
- 作者待核实可以与可播放音频一起交付；缺用户封面注明待补。身份或完整性未通过则交付为明确标识的候选／摘录，不使用无条件“Verified”名称。
- 报告分列：曲目身份、版本／完整性、边界、音频导出、标签／封面、试听、音源质量。总状态不能高于用户目标所要求项目中的最弱项。

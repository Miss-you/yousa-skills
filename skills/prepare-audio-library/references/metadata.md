# 音源质量、封面与音乐署名

## 更好音源

先查对应发行的官方页面、唱片商品／数字发行、作者或厂牌说明。记录可获得格式与日期、版本、实际取得方式；平台订阅资格不自动意味着可以下载可导出的音频文件。资料不明确时，不宣称平台提供某编码或无损。

取得文件后比较编码、码率、采样率、声道、时长、削波、明显频谱异常与录音版本。跨编码不能直接按码率排名；频谱截止只能作为线索，不能认证无损。参考曾经过未知转码时保留溯源限制。只有同一录音、合理对齐且音量匹配的试听才支持听感比较；未做盲听不要声称盲测更好。

## 字段与证据

| 字段 | 可用依据／规则 |
| --- | --- |
| Title | 官方该版本曲目表；仅第三方命名时标暂定，保留原始名称 |
| Artist | 与该录音对应的表演／发行艺术家署名；不把视频上传者、角色名或翻奏者当原版作者 |
| Composer | 逐曲作曲署名；区分作曲、编曲、原主题作曲、音乐总监、演奏和歌唱 |
| Album artist | 优先官方该发行署名；未知可用 Various Artists 作为本地归并惯例，明确其性质 |
| Album／Track／Disc | 与目标合集及实际交付顺序一致；自选曲序标为本地整理，保留官方序号映射 |
| Date | 对应所标专辑／版本的发行或上线日期，区分原版、精选、游戏发售与视频上传日期 |
| Genre | 可用 Game Soundtrack 等合理本地分类，无需假装是官方分类 |
| Cover | 用户提供的图片；默认保留构图、宽高比，缺图不擅自替代 |

作者核查顺序：官方逐曲册页／发行 credits、作者本人逐曲公告、制作公司资料、可追溯数据库，再到上传说明和用户制谱。多处转抄不能算独立来源。官方姓名名单也可能只对应整部游戏；没有曲目映射，个人 Composer／Artist 仍留空或保留用户已有可靠值。游戏级团队信息写来源说明，不塞入每首的 Composer。

交叉检查同名异曲、翻奏、原版／重编版、标题语言与长度。若源内包含旧作品主题，也不能仅靠辨认旋律断定整个新曲的作曲或编曲署名。不要把 Nintendo 等发行方自行写成作曲者。

找不到署名时具体报告“核实到谁参与哪一层级、还缺哪首的对应证据”，并列来源链接；不虚构、不反复搜索相同词、不阻塞已可完成的音频处理。后续有新证据再补标签。

## 嵌入封面与标签

使用可用的 ffmpeg／mutagen 等工具；先检查依赖，不硬编码某台机器的 Python 路径或临时安装位置。依赖缺失可在隔离环境安装，不升级系统环境来完成普通打标签。

- MP3：ID3 APIC，front cover 类型 3，正确 MIME。按播放器选择 ID3v2.3／2.4；日期转换后读回年月日，有些界面只显示年份。
- Opus／Ogg：Vorbis Comment 的 `METADATA_BLOCK_PICTURE`，值为 base64 编码的 FLAC Picture 数据块，设置 front cover 类型、MIME 和尺寸。只设置视频流元数据不足以保证封面标签兼容。
- AAC／M4A 等：使用对应容器的封面／标签方式，如 MP4 `covr`；不能套用 ID3。遇到其他格式查官方工具文档。
- 写入前保存既有标签，按本轮范围更新；保留多艺术家、歌词、ReplayGain 等无关信息。封面更新应有明确的替换规则，避免不断累积重复封面。
- 正常打标签无需重编码音频。修改前后比较音频负载哈希并读回新增字段及图片内容；完整文件哈希可改变。原图外置副本仅作为补充。

如果目标播放器无法显示已嵌入图片，先检查支持格式、图片类型与缓存；只有有证据表明需要转换时，生成兼容图片副本并保留原图。裁切或创意修改需用户提出或确认。

## 最终交付核对

对每种格式确认曲目数量、标签值一致性及用户图片已嵌入。压缩包必须包含最终写完标签的文件；逐项校验压缩包成员与磁盘最终文件一致。报告里注明标准标签读回和真实播放器显示分别是否验证。

# Writing Conclusion-First Briefs

## Overview

Lead with a bounded answer, then earn it with traceable evidence. Optimize for a reader deciding whether to keep reading, trust the conclusion, or act next.

## When to Use

- Writing a durable Markdown research brief, investigation summary, retrospective, decision memo, or evidence synthesis.
- The reader must find the answer before background or chronology, then decide whether to trust it or act.
- Not for raw meeting notes, step-by-step tutorials, or a one-line status reply with no reasoning to preserve.

## Workflow

1. Define one core question, an as-of date, the evidence window, and source boundaries.
2. Calibrate depth. For a routine update, use a conclusion plus a few verified bullets. Use the full structure only when reasoning, uncertainty, or durable context matters.
3. Write the executive conclusion first. State the answer, confidence, scope, and most important caveat in 1–3 short paragraphs.
4. Add only background needed to understand the question; do not narrate discovery order.
5. Explain what was done: sources checked, comparison window, method, exclusions, and failed or stale inputs that affect confidence.
6. Build the evidence chain. Keep these categories distinct:
   - **Observed fact:** directly measured or recorded.
   - **Source claim:** asserted by a named source; do not restate it as fact.
   - **Inference:** interpretation supported by stated evidence and alternatives.
7. Put links beside public claims and use exact dates for changing facts. Summarize private evidence with counts, ranges, and paraphrases unless disclosure is explicitly authorized.
8. Use the detailed conclusion to explain causality, rejected alternatives, and boundaries. Do not repeat the opening verbatim.
9. End consequential briefs with limitations, falsifiers, and concrete next checks. Remove sections that add no decision value.

## Default Markdown Skeleton

```markdown
# <Title>
- As of: <date/timezone>
- Evidence window: <range>

## Conclusion
<Direct answer, confidence, scope, caveat>

## Background And Question
<Only context needed to understand the decision>

## What Was Done
<Sources, method, comparisons, exclusions>

## Evidence And Reasoning
### <Claim or finding>
<Observed fact / source claim / inference, with nearby links>

## Detailed Conclusion
<Why the answer follows; alternatives and boundaries>

## Limitations, Falsifiers, And Next Checks
<What is unknown, what would change the answer, what to verify next>
```

## Quick Reference

| Need | Rule |
| --- | --- |
| Fast comprehension | Answer before background |
| Trust | Show window, freshness, method, and nearby sources |
| Precision | Separate observation, source claim, and inference |
| Brevity | One idea per section; delete repeated conclusions |
| Honest uncertainty | State confidence and falsifiers |
| Proportionality | Collapse trivial updates to verified bullets |

## Common Mistakes

- **Chronology first:** Move the answer above the research diary.
- **Three conclusions:** Keep one executive answer; make later analysis additive.
- **Citation dump:** Attach each source to the claim it supports.
- **False certainty:** Name who made a forecast and what remains inferred.
- **Template worship:** Omit empty or low-value sections.
- **Action without evidence:** Tie every next step to an unresolved risk or falsifier.
